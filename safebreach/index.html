Case study · SafeBreach · 2019–2021

Making attack simulation results readable, in our product and in Splunk.

SafeBreach is a breach-and-attack simulation (BAS) platform: it runs simulated attacks against a company’s own environment to show which security controls catch them and which don’t. I designed data-heavy workflows for the platform, its integration with Splunk Mission Control, and a new design system that I rolled out with the front-end team.

My role
UX/UI Designer
Scope
Platform workflows, Splunk integration, design system
Worked with

01 / The platform

One screen for what’s running, what ran, and what’s next.

A test can run a huge number of simulations across many security controls and machines. The main screen brings the live test, the history and the queue together, and the navigation follows the job: Simulate, Prioritize, Mitigate.

01.1While a test runs

Results as they come in

  • StatusEvery simulation lands in one of four outcomes: missed, detected, stopped or prevented. The donut shows the split live.
  • Security controls by categoryDLP, web, endpoint, email, network inspection, network access, containers and cloud, each with the tools being tested and its progress.
  • Top attack types and simulatorsWhich kinds of attack are running most, and on which machines.
  • Test timelinePast tests grouped by day, with the controls involved, the number of simulations, the share not blocked, and a status donut per test.

States, not just a happy path

02 / Splunk integration

Bringing SafeBreach into the analyst’s investigation.

Security analysts work their alerts (“notables”) in Splunk Mission Control. I designed how SafeBreach shows up there, so an analyst looking at a suspicious host can see how exposed it is without leaving the investigation.

The flow
Notable in Mission Control→SafeBreach tab→Run a blast radius test→Drilldown→Mitigate
02.1Inside a notable

From “no results” to a risk score in one click

02.2Drilldown

From exposure to action

  • Attack surface by MITRE tacticThe host’s exposure across tactics from initial access to impact, colored by severity.
  • Mitigation insightsWhat the simulations found, with severity, control, target and number of attackers, and a Mitigate button on every row.
  • Blast radiusWhich tactics worked on this host, and which critical assets it can reach from there: a PCI segment, a payment application, a production database.

03 / Design system

A new design system, rolled out with front-end.

I created SafeBreach’s new design system and rolled it out together with the front-end team: typography, color, components, and written rules for how they behave.

  • Alerts always sit at the topA dismissible alert covers the content. One that can’t be dismissed pushes the content down.
  • Some errors stayPermanent errors have no close button.
  • Success gets out of the waySuccess messages close on a timer, and can also be closed by hand.
